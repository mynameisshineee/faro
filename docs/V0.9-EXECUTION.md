# llminbox v0.9 — Trustworthy Coordination Kernel

Status: software candidate completed and operational pilot certified for `a0cfc2e`
(2026-09-07); see [V0.9-CERTIFICATION.md](V0.9-CERTIFICATION.md).
Public publication remains subject to the human/legal gates in
[`RELEASE-CHECKLIST.md`](../RELEASE-CHECKLIST.md).

## Objective

Produce a reproducible v0.9 pilot in which every native operational write has a
server-derived principal, role, runtime instance and lane; messages are
idempotent and return durable receipts; large-ledger search is paginated and
benchmarked; runtime sensors emit OpenTelemetry-compatible data; and one Docker
lane passes the scoped identity, admission, delivery, recovery and rollback
falsifiers listed in the certification.

The pilot is complete because both executable controls and deployed evidence exist;
it is not broadened beyond that evidence. In particular, it does not claim HA,
network-partition tolerance, 16-agent load, hostile-host isolation, physical-volume
recovery or exactly-once third-party effects. See
[`V0.9-CERTIFICATION.md`](V0.9-CERTIFICATION.md).

## Current base

- The integrated candidate contains the V8 corrective base plus the M1–M5
  workstreams. Release identity is the final candidate commit and artefact digest,
  never a commit count or a branch name.
- `llmi post` selects the native path where configured. A local markdown fallback
  remains available for legacy/narrative operation, but is forbidden as an
  authoritative fallback in `native-required`.
- `roster.json`, operator credentials and workload credentials are deployment-local
  and excluded from source control. Native identity derives principal, role,
  runtime instance, lane and capabilities from the authenticated session.
- The certified deployment used Compose project `llminbox-v09-cert` on port 18099,
  then returned to the base `servicio:app` service without deleting volumes and
  with the native journal preserved.

## Operating model

The primary checkout is integration-only. Work that changes files must use a
dedicated worktree and a `codex/llminbox/<workstream>` branch. Never reset,
clean, rewrite or delete another worktree. Do not deploy, merge to `main`, push,
or prune branches without an explicit integration order from `codex-llminbox`.

At most three implementation workstreams may be active. Investigation and
review may run in parallel but must not silently broaden their scope.

Every delivery states:

1. exact base and resulting SHA;
2. files and contract changed;
3. positive and negative controls executed;
4. remaining counterexample or uncertainty;
5. rollback command or procedure.

Coordination belongs in the configured `LEDGER.md` for the `llminbox` lane. Use
the validated writer. Ephemeral progress chatter does not belong in the ledger.

## Authority split

- `codex-llminbox`: product authority, architecture, integration and release.
- `engineering-manager`: WIP, dependencies, ownership and delivery accounting.
- `cto`: technical design review and cross-workstream invariants.
- `security`: identity, authorization, secrets and isolation falsifiers.
- `sdet`: executable acceptance matrix, concurrency and recovery falsifiers.
- `backend`: event/write-path domain implementation.
- `db-migrations`: durable state, migrations, FTS and benchmarks.
- `infra`: runtime identity, container topology, deployment and rollback.
- `cpo`: public product surface, migration story and open-source usability.

Harness owns agent definitions, ICM and eval design. llminbox owns runtime
coordination state and enforcement. Agent runtimes execute work; they do not
self-certify identity or health.

## Milestones and gates

### M0 — One truthful V8 base — complete

- Corrective branch is integrated without regression.
- Full local suite passes.
- V8 adversarial falsifiers pass.
- Deployment identity, attestation and rollback can be measured.
- README and SECURITY do not claim more than the implementation enforces.

### M1 — Authenticated native write path — implemented

- Distinct principal, role, runtime instance and lane.
- `/whoami` is server-derived.
- Native message/event write uses an idempotency key and the identity and
  authority model in `ADR-001-NATIVE-AUTHORITY.md`.
- A successful mutation returns a durable receipt.
- Same key plus same body returns the original result; same key plus a different
  body is rejected without mutation.
- `llmi post` uses the native path in pilot mode. Legacy/local fallback is explicit
  outside pilot mode and prohibited for a native-required authoritative write.
- Shared token cannot perform a verb made native-required for the pilot lane.
- Work ownership uses expiring leases plus monotonic fencing; a stale owner
  cannot mutate after takeover.
- Commands carry causality, revision and supersession; an older delayed command
  cannot execute after a newer one is accepted.

### M2 — Search — implemented

- FTS5-backed search, keyset pagination, snippets and explicit truncation.
- Filters for lane, ledger, actor/principal, type and time.
- Benchmark on real ledgers plus a one-million-entry generated corpus.
- Recall fixture built from real operator questions.

### M3 — Runtime sensors — implemented, opt-in export

- Lifecycle events are emitted by the runtime/supervisor, not inferred from
  agent prose.
- OpenTelemetry-compatible export for starts, stops, heartbeats, jobs, tool
  failures, retries, policy denials and receipts.
- Sensitive prompt/tool content is disabled by default.
- Export is disabled by default. Enabling an OpenTelemetry-compatible exporter is a
  deployer action; observability never becomes the authority record.

### M4 — One-lane Docker pilot — certified within stated limits

- No ledger mounted inside the agent container.
- Scoped repository and knowledge mounts.
- Per-runtime credential and authenticated coordination gateway.
- Positive native admission/delivery/idempotency, pre-admission readiness and
  operator-only barrier controls.
- Close/drain/seal/certify rollback with zero pending, failed and unresolved work;
  base-compose restoration without volume deletion and with the journal preserved.
- Cross-lane and stale-identity behavior has executable coverage, but the deployed
  certification does not claim an offensive all-lane audit or 16-agent concurrency.

### M5 — Release candidate — software complete, publication gates open

- Architecture, threat model, migration and operational runbooks.
- Reproducible package/image, changelog and versioned protocol.
- Existing and new tests green for the candidate evidence recorded on 2026-09-07.
- Documentation distinguishes legacy, bridge and native-required behavior.
- Publication is blocked until a human closes ownership/chain-of-rights, trademark,
  complete third-party notices and a verified private security-reporting channel.

## Executed pilot result

The deployed run began with `/live` returning 200 and `/ready` returning 503. The
operator opened the `events.accept`/`outbox.requeue` pair at epoch 1, after which
`/ready` returned 200. Event `evt_89c14407d64d45c8b18ca108f8b614c2`
returned receipt `rcp_4ae444aad19b424288af35e548336d71`; exact replay returned
those same identifiers and left one ledger entry.

Rollback closed the pair at epoch 2, drained it, sealed it at epoch 3 and recorded
an atomic certificate at `2026-09-07T04:33:58Z` with
`pending=0`, `failed=0`, `unresolved=0` and `durable_v6`. The pilot overlay was
then removed without deleting volumes; base `servicio:app` became healthy and the
journal remained present. Reproduction commands and caveats are in
[`V0.9-CERTIFICATION.md`](V0.9-CERTIFICATION.md).

## Product boundaries for v0.9

No new chat UI, vector database, Kubernetes, general-purpose agent framework or
full Agent OS implementation. SQLite remains the single-node store unless a
benchmark proves it is the limiting component. Markdown remains a supported
bridge and export format, but legacy direct appends are explicitly unverified
and cannot have operational authority in pilot mode.
