# Release checklist

> **Status: the single-lane runtime exercise is certified for `a0cfc2e`**, recorded in
> [`docs/V0.9-CERTIFICATION.md`](docs/V0.9-CERTIFICATION.md). That evidence closes the
> operational pilot gate **for that tree only**: it does not carry to a different artefact
> digest — item 4.5 says so and this line does not weaken it. The legal, third-party
> notice, private security channel and publication-authority items below still require
> human closure; **a certified exercise is not a released artefact.**

> **What the artefact is.** The 1.0 artefact is the **OCI image** and the **`git archive`
> tarball**. **The repository is not the artefact**: it is the place of work. Opening the
> repository is a separate decision and **not part of the 1.0** — it queues behind it.
>
> **The open-source repository is a new artefact**, not a mirror and not a push of the working
> repository. It is created **without the history** of the current remote, carrying the
> publishable content only; `docs/evidence/` and `fleet/` do **not** travel; and **nothing is
> deleted from the working repository**, which stays whole. The reason is mechanical:
> `export-ignore` governs `git archive`, **not `git push`** — a push publishes tree *and*
> history, so deleting those paths at HEAD would leave them in yesterday's commits, and
> rewriting history is forbidden by item 5.2.
>
> **It is built from an ALLOWLIST** (`OSS-MANIFEST.txt`): what gets published is **declared**,
> and anything not declared does **not** travel. A denylist would have to enumerate everything
> that must not ship, which never ends and **fails open** — anything forgotten travels. Build it
> with `tools/materializa-oss.sh <commit>`, which materialises the artefact, compares it against
> the manifest in **both** directions and prints the two shas plus the `md5` of the file list.
> Falsifiers, and the second is the one that protects: ⊕ everything present in the OSS artefact
> appears in the manifest, and `git log --oneline -- docs/evidence fleet` there is **empty**;
> ⊖ the same command in the **working** repository still returns its commits — if that one is
> empty too, evidence was destroyed instead of excluded, which this ruling forbids.
>
> ⚠️ **Item 5.5 gates publication**: publishing before the private security channel exists means
> publishing with no way to receive a vulnerability report. Creating the repository **empty and
> private** breaks nothing; what is gated is **what gets pushed and when it becomes public**.
> **Each vehicle needs evidence for the release commit.** `tools/build-release.sh`
> builds and compares OCI archives; `tools/materializa-oss.sh <commit>` creates the
> manifest-filtered source tree. The source tarball is generated by `git archive`
> and must pass item 4.7 for that same commit. The presence of these tools does not
> certify a newly integrated commit or transfer an earlier image's evidence to it.

Run top to bottom. **Every item has a falsifier — the observation that proves it is
not done.** An item without an executed falsifier is not done; it is declared, and
this project has already shipped enough declared-green checks to know the
difference.

Nothing here is a formality. Each line exists because its absence caused something.

## 5 · Legal and organisational gates

These are **named here in full and resolved elsewhere**. Naming them is not the same
as negotiating them: a public checklist is a poor place to work out a legal position
and a worse place to publish a half-finished one, so each row states *what* must be
closed and *nothing about its current state*.

| | Gate | What closes it |
|---|---|---|
| **5.1 · Ownership** | The copyright holder named in `LICENSE` and `NOTICE` is the entity that actually holds the rights | A holder that is a legal person, stated consistently in both files. **Not touched by any commit on this branch.** |
| **5.2 · Chain of rights** | The provenance of every contribution behind that holder is documented | Every author identity in `git log` covered by a written record. Going forward this is what the CLA is for; the DCO sign-off is the record of how contributions
were certified before it, it does not apply retroactively, and history is not rewritten to fake it. |
| **5.3 · Trademark** | A prior-rights search for the project name, before the name is used commercially | A dated search report. A zero from a search tool that did not respond is not a report — it is the same zero a free name would give. Until it exists, no `™` and no "registered trademark" anywhere (item 3.4). |
| **5.4 · Third-party obligations** | No attribution obligation left open by items 0.3, 0.4 and 4.2 | Licence texts of everything the image redistributes, collected and shipped. `NOTICE` asserts no licence it has not read. |
| **5.5 · Security reporting channel** | A private channel that is confirmed to exist and be monitored | Opening the repository page and seeing the private reporting form offered, or a monitored address published in its place. **`SECURITY.md` currently states this as intended, not available** — publishing while that is still true means publishing without a way to receive a vulnerability report. ⚠️ **The first branch of this falsifier is gone**: with the artefact declared as image + tarball, there is no repository page to open, so the route is the **second** one — a monitored address published with the artefact. Nothing new to invent; the branch has to be chosen. What the row already warns stays red and is not closed by this: `SECURITY.md` declares the channel *intended, not available*. |

**None of these is settled by merging a pull request.** If you are reading this as an
outside contributor: they do not affect your ability to use, fork or contribute to
the code under Apache-2.0, which is what the licence in this repository says and
means.
